# Optional recorded chime audio: integration contract

Source candidate on `befbc9abc7cc197f7567ae48862aa46ced6f5b4c`. This folder is a testable audio component, not an installed feature. No current HTML, Worker dispatcher, artwork, Daddy module or game source is changed. The current catalog deliberately remains `qualityReviewed=false`. No live playback can be enabled through the normal engine until listening clearance is explicitly supplied in a separately reviewed integration.

## Components and ownership

`RecordedChimes` replaces the older audio module's implementation and retains its constructor/unlock/play/setVolume/stop/destroy interface. It receives `getContext:()=>AudioSys.getCtx()` from the app; import, construction, mounting and stored preferences never call that getter. It never creates or closes a live AudioContext. The optional `getOutput(ctx)` defaults to the shared context destination; only the isolated verification fixture uses OfflineAudioContext output.

`installChimeSoundControls` binds to the existing ChimeController. It creates no engine or context. Its independent key is `ohana_chime_sounds_v1`; it never reads/writes/aliases Daddy's `ohana_daddy_sounds_v1` or master `ohana_muted`. It uses the controller's existing `.18` volume as the default (36% of the established `.5` cap), preserving the old chime pause preference. Volume is stored normalized 0–1 and mapped to the old controller's 0–.5 range. Mute is persistent, but enabled sound consent is not restored automatically. An explicit trusted Unmute/Enable gesture calls the existing controller. Imported/stored settings, sliders, cross-tab updates and render notifications never unlock playback. Restored unmuted intent can show a separate **Enable for this visit** button; the mute toggle always remains a mute toggle.

Pass `getGlobalMuted` from both `AudioSys.muted` and `ohana_muted` (catch failure as muted). Wire `RecordedChimes.isMuted` to the new control instance's `.isMuted()`; before that instance exists, return true. Existing Settings Enable is redirected through the same deliberate gesture path while bound, and restored on destruction. The current Daddy panel stays untouched and adjacent; own-panel mutations are excluded to prevent cross-observer refresh loops.

## Host context and lifecycle

`audioHostContext` / `createHostAudioGuard` use only sanitized state, supplied after the app validates its current stored token. Required identity fields are authenticated, memberId, numeric sessionRevision, roomId/roomEpoch, gameId/type/gameEntryVisit, Puzzle ID, tab/activity and activity-specific record/page ID. `eligible` must be explicitly true for a validated painted owner or visible sound controls; missing eligibility parks audio. `visible`, `appInert`, paused and reducedMotion describe the actual current painted surface, not a guessed scene name. No raw token may enter this component, snapshots, routes or logs.

HF, TEN, Rummy and Spades may all report the same `home` scene: their IDs and visit generations must still differ. Ordinary polls, card selections and growing hands leave the context stable. Current Music can leave S.game selected while setting #app inert/hidden: observe that actual overlay and pass appInert=true, so the underlying controller is parked. Unknown/hidden attachment owners are ineligible; this audio work does not invent artwork anchors.

Create one guard for the existing controller, then call `guard.refresh()` on real room/table/activity/overlay transitions, validated session changes, visibility/pageshow/reconnect and motion changes. An eligible stable poll needs no reset. Keep the returned context as the current accepted mount stamp; the engine's isActive getter must freshly compare current sanitized session/route/visibility to that stamp as well as controller.active. Refresh after every awaited import/resume/decode/mount boundary. Route change calls controller.reset, invalidating pending audio/normalization by generation; it does not write game or preference state.

When Bridge sound controls are the active surface, park the artwork and set an empty `bridge-audio-controls` rig list before allowing manual unlock. Do not run automatic strikes behind Bridge or another modal. On return, revalidate the actual game scene, restore validated rigs and schedule a fresh interval, with no missed-strike burst. On hidden/pagehide/unknown scene/logout call guard.stop immediately; the audio module also stops on hidden/pagehide and watches host eligibility while a source exists. Pause/visible/scene changes in the existing controller already stop sources. Reduced motion keeps static rigs and suppresses automatic contacts; explicit controls remain accessible. Never wrap render, game input, history or dialog methods to implement this.

Destroy in owner order: controls.destroy, guard.destroy, controller.destroy (which destroys its audio). All audio stop/destroy calls are idempotent, abort pending fetches, discard stale decoded/analysis completions, release nodes and remove the bounded source watcher. The app owns and retains its shared context. The guard owns no RAF, timer or DOM observer; the future runtime's existing host observer must call it for the documented state changes.

## Signal bounds and unchanged recordings

Original MP3 bytes and CC0 source evidence are preserved under audio/. The old catalog's provisional gain numbers are retained as provenance but are not multiplied again: playback now uses measured per-recording peak gain, capped at 12×, targeting at most .5 peak per channel. Master gain is capped .5 and voices at 2, giving a conservative summed sample bound of .5 before output-device effects. Playback rate remains exactly 1. Mono is explicitly upmixed to stereo; stereo channels are preserved independently, never summed into a potentially cancelling mono signal. Fades remain brief and natural-decay oriented.

Production normalization yields around a 3ms budget between small sample chunks, rechecking generation/eligibility. This is a cooperative target, not a hard real-time bound. Browser measurements and cold-start overshoot are recorded separately. It runs after decode once per recording, not per strike or animation frame.

The loader also rechecks generation, context, AbortSignal and host eligibility before fetching, before reading a returned body, before decode and after decode. A late response/body from an abort-ignoring source is skipped without starting stale decode. A browser decoder already running at cancellation cannot be forcibly aborted; its result and analysis are discarded.

Coverage limit: the saved OfflineAudioContext cancellation graphs cancel scheduled sources **before rendering begins**. They prove scheduled-source retirement and zero rendered output for those cases, not audible mid-playback cancellation. Models separately test lifecycle ordering. A speaker-suppressed running-graph cancellation check remains required after real host integration; no human listening or physical-device claim follows from the offline graphs.
