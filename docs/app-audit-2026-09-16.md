# Ohana Home audit — September 16, 2026

Scope: the six existing games and their shared navigation, rooms, profiles, chat, invitations, notifications, audio, accessibility, and responsive layout. Ohana 10 is still a separate, unfinished feature; it is not included in this release.

## Current-game protection

No live game rows, scores, deals, accounts or session tokens were edited for testing. No schema migration or historical score recalculation. All gameplay verification uses synthetic fixtures or an in-memory SQLite database.

Fixed a genuine race: game chat previously saved an entire stale state, potentially overwriting a simultaneous move. Chat now retries against the newest state. Every human game move now uses a guarded save checking state, turn and playing status. Bots have the same status guard and retry state conflicts. Starting and canceling waiting tables also check the saved status and player list, preventing a stale action from replacing/deleting a newly started table.

## Engines

- Words rejects duplicate squares and non-integer coordinates before changing state. Verified combined DW/TW, letter-before-word bonuses, zero-value blanks, no reuse of existing premiums, and Robin Hood awarding other players. The 225-cell board remains intact.
- Checkers enforces available captures. The UI highlights only legal capture destinations, and all bot difficulties plus the hard search follow the same rule.
- Memory and Tic-Tac-Toe reject invalid coordinates. Memory now sends only revealed/matched card identities; private computer memory is omitted from the response.
- Hand & Foot: existing multi-group opening, separate concealed foot, foot pickup timing, red-three replacement, books, four-round progression and computer legality suites pass. Existing tables retain their original rules/version and scores.
- Mahjong: stacked/free tile validation, generated solvability, reshuffle and revision checks pass.

Rules checked against [Hasbro's Scrabble instructions](https://www.hasbro.com/common/instruct/Scrabble_(2003).pdf) and [Bicycle's Hand and Foot guide](https://bicyclecards.com/how-to-play/hand-and-foot). Ohana uses documented house variants (individual Hand & Foot and mystery squares); these are not claimed as universal rules. See handfoot-rules-audit.md for the variant differences.

## Layout and usability

Full-width board remains default. Score total and player share a compact line; word/bonus summary remains visible and detailed arithmetic expands on demand. Replay keeps an accessible label. Chat has one emoji-picker button, message field and send button. Drafts survive failed sends. Tray surrounds its content; on phones its six controls form two rows of three. Next game remains in those controls. Hand & Foot removes empty-meld filler and extra instruction spacing while preserving larger illustrated cards and a visible foot pile.

Art, characters, voice/mute preferences, scripture and correct pillow remain unchanged. Accounts are never logged out by this update.

## Verification and limits

All 29 pre-existing test scripts passed before editing. The final changes were exercised by the full suite plus new engine-integrity and chat-drafts scripts, with affected bot, room/concurrency, Hand & Foot and accessibility suites rerun after follow-up changes. New SQLite races explicitly check that chat retains a newer board and stale moves cannot overwrite a committed turn.

Browser inspection uses /layout-preview, which embeds the real fictional practice page in a 390px or 864px viewport, exercising actual media queries. The fixtures have no account authentication or real game actions. This is responsive browser testing, not a claim of physical Android/VoiceOver testing. The accessibility suite checks keyboard navigation, focus preservation, labels, dialogs and automated axe checks; color-contrast and region rules are not included in that automated scan. Push encryption/signatures and routing are tested locally; delivery through a user's device notification settings cannot be certified here. Browser speech synthesis voices depend on the device.
