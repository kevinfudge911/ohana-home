# Memories and megaphone media integration

Prepared on published camera/badge baseline 3e7fe6e98aa7da0133af0e61a150cd6cf52f36fb. This sealed candidate is local; no production upload, game move or announcement was performed.

Memories adds explicit album creation/destination/move controls and JPEG/MP4/WebM memories, with videos limited to 20 MiB. Uploaded originals, thumbnails and the six room-frame selections require current family-room membership. Ownership and moderation rules stay unchanged. Video bytes use atomic 1 MiB D1 parts; playback is an authenticated full fetch into a Blob, without streaming range support or transcoding. Existing publicly embedded built-in artwork/photos remain public; this change makes no blanket privacy claim about them.

The corrected Memories session guard invalidates identity, token, room and request epochs on account changes, aborts private fetches, clears rendered media, revokes Blob URLs and requires explicit reauthentication. Retained Move/open handlers and delayed replies cannot reuse the previous identity. The reviewed correction is included in full.

The existing megaphone composer accepts up to two selected pictures/videos, with an 8 MiB aggregate source limit. Selection and Preview stay local. Only explicit Send invokes the new atomic media/announcement/recipient/history transaction. A stable request UUID deduplicates retries of the same prepared draft; changed bytes under that UUID are rejected. Only the sender or an original recipient who still belongs to the room can fetch the private attachment. Account changes permanently invalidate a captured or closed composer. Existing Menu pictures, text-only notices, acknowledgements, reactions and private replies are preserved. Deployment of this feature does not send an announcement; the Rummy announcement remains held.

The whole-application inverse restores the exact published baseline. The Worker inverse removes only Memories API changes and announcement hooks, preserving auth, PuzzleRoom, game validation and music. Independent source-patch replay matches all four changed/new runtime sources exactly. Camera behavior, direct Play, Home order, Bridge, TEN/Rummy art and controls, engines, bindings, credentials and existing family media remain unchanged. Main HTML has 32 executable scripts. Deterministic gzip expands to the exact source; all 483 dry-run modules match their source bytes. Upload: 62,668.46 KiB.

Checks: actual SQLite API and DOM fixtures for both features; stale account/deferred response guards; legacy Menu behavior; 79 direct-navigation assertions in 12 contexts; 18 Home-order, 45 human-badge, 199 Bridge-context, 71 Bridge-dispatch and 18 header-ownership assertions. Browser QA uses generated JPEG, H.264 MP4 and VP8 WebM only, with loopback SQLite and supported CUA. Memories upload/play/pause/seek and account-change clearing pass for both formats; six frame masks align with the room art at desktop, phone and landscape. Composer JPEG/MP4/WebM phone cases and JPEG tablet/desktop/landscape cases pass selection/Preview locality, explicit Send, lost-confirmation retry, recipient display/playback, stale-context blocking and unauthorized-send denial. No external broadcast or family-state mutation occurred.

Limitations: physical iOS/Safari, audible playback, large-clip D1 latency and weak-network behavior are not certified. Browser clips are small and muted for testing. Existing built-in public artwork is unchanged. Final independent integration review remains required before release.

Run with the existing Node, jsdom and test dependencies: tests/media-integration-preservation.cjs, tests/media-packaging.cjs, tests/media-routing.cjs, tests/memories-media.cjs, tests/memories-session-boundaries.cjs, tests/megaphone-media.cjs and tests/megaphone-legacy-compat.cjs. The two feature preservation entrypoints delegate to the stronger combined inverse. Supply OHANA_TEST_GIT if Git is not on PATH and OHANA_PACKAGE_OUTDIR to verify the dry-run module directory. Rebuild only with node scripts/package-main-html.cjs after any HTML change.
